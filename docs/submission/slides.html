Upstage 기술

Studio 에이전트가 문서 처리의 핵심, Solar Pro 4 가 행동의 두뇌

Studio 에이전트 (Parse → Classify → Extract ×2)

  • Classify 가 pay / apply / info / ad 로 가르고, 납부·신청 문서만 Extract 로 분기합니다. 광고는 의도적 미매핑.
  • include: ["all"] 로 필드별 confidence·좌표를 받습니다. low 인 값은 음성으로도 화면으로도 읽지 않습니다.
  • Classify 의 범주가 low 여도 점수 ≥0.9 면 추출을 계속하고 대조로 판정합니다(법원 결정문 케이스).

Solar Pro 4 브라우저 에이전트

  • 페이지의 접근성 트리(버튼·입력·링크 + 참조 번호)를 읽고 click / type / press / scroll / wait_human / done / abort 중 한 번에 하나만 결정합니다.
  • 픽셀 computer-use 가 아닙니다. 이미지를 받지 않고 구조를 읽습니다.
  • 가드레일은 코드에 있습니다: 비밀번호·인증 문구가 보이면 모델을 부르지 않고 사람에게, 납부 버튼은 문서 금액이 보일 때만, 허용 도메인 밖 차단.

실측 함정도 기록했습니다 — 초안 config 는 API 에서 안 보임 · 미설정 노드가 있으면 저장 거부 · ["last"] 면 confidence 가 사라짐 · 미매핑 타입은 Extract 단계가 응답에서 통째로 빠짐.

왜 사람에게 넘기나

인증·비밀번호·약관 동의는 법적 행위입니다. 에이전트는 그 화면을 보는 즉시 멈추고, 보호자가 마친 뒤 [이어서 하기]로 재개합니다. 원격 입력은 저장하지 않고 끝나면 비웁니다.

시연 포털

실제 인터넷지로는 비회원도 금융인증서가 필수라 조회조차 인증 뒤에 있습니다. 그래서 같은 흐름의 시연용 포털에서 처리하고, [실제 인터넷지로에서]는 인증 벽에서 보호자에게 넘어오는 것까지 보여줍니다. 실기관 연동은 원장을 기관 API 로 바꾸는 일이지 에이전트를 바꾸는 일이 아닙니다.

공공부문 활용 — 경북

바꿀 것은 하나: "자녀 화면"에 누가 앉는가

① 생활지원사 사례관리

노인맞춤돌봄 생활지원사가 방문 때 우편물을 찍으면, 보호자 화면이 곧 사례관리 화면. 누가·무엇을·언제까지·처리 여부가 기록으로 남는다.

② 읍면 행정복지센터 · 경로당

폰이 없는 어르신은 창구·경로당 태블릿에서 같은 흐름("우편물 읽어드림"). 어르신 쪽엔 계정이 없어 기기가 누구 것이든 된다.

③ 경북 기관 레지스트리

23개 시군의 지방세·상하수도 고지서 공식 번호·계좌를 도 차원에서 등록 → 경북 공공 고지서 전부가 대조 대상. 모델 개발이 아니라 데이터 등록. 사칭 의심 패턴은 지자체·경찰로.

④ 공공 납부 API

위택스·지로가 API로 열리면 원장만 교체. 에이전트는 그대로, 인증은 여전히 사람.

가족이 있으면 가족을 돕는 도구, 가족이 없으면 공공이 그 자리에 앉는 도구.

한계 — 먼저 밝힙니다

이 결과가 말하지 않는 것

탐지하지 못하는 것

  • 공식 연락처를 그대로 복사한 사칭 — 대조할 값이 전부 진짜라서 이 방식으로는 못 잡습니다.
  • 하위 조직 표기(예: 국민연금공단 포항지사)는 구조만으로 진위를 가를 수 없어 둘 다 자녀 확인으로 보냅니다. 오탐을 감수하고 미탐을 줄였습니다.
  • 계좌의 실제 명의는 조회하지 않습니다(권한 없음). 화면에 "확인하지 않음"으로 표시합니다.
