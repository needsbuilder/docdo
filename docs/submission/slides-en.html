DocDo

Seniors photograph a letter and hear what it says. Their adult children see it checked against official records and approve. An agent completes the task. A person handles the authentication.

docdo.vercel.appgithub.com/needsbuilder/docdo

The problem

For a low-literacy senior, mail is not a reading problem. It is a judgment problem.

What is this?

Bills, notices, collection letters and ads arrive in the same envelope. Reading the words does not tell you which one it is.

Is it real?

Impersonation letters keep the amount and due date intact and change only the phone number or the account.

What should I do?

"Just pay it" is the sentence that moves money. No one should have to decide that alone.

So the senior's screen only explains, reassures and warns. Every action moves to the child's screen.

DocDo4

Upstage at the core

Studio handles the document. Solar Pro 4 decides the next action.

Studio agent: Parse → Classify → Extract ×2

  • Classify splits documents into pay / apply / info / ad. Only pay and apply reach Extract. Ads are intentionally unmapped.
  • Calls use include: ["all"] to get per-field confidence and coordinates. A value marked low is never spoken or shown.
  • If Classify's label is low but the score is ≥ 0.9, extraction continues and the verification layer decides.

Solar Pro 4 browser agent

  • Reads the page's accessibility tree (buttons, inputs, links with reference ids) and picks exactly one action: click, type, press, scroll, wait_human, done, abort.
  • Not pixel computer-use. It never sees an image; it reads structure.
  • Guardrails live in code: any password or certificate prompt hands over to a human before the model is called; pay buttons only when the document amount is visible; no navigation outside the allowed domain.

Platform findings we documented along the way: draft configs are invisible to the API · an unconfigured node blocks saving · ["last"] drops confidence · an unmapped type removes the Extract step from the response entirely.

DocDo5

Safety principles · they override every other decision

The senior's screen never leads to money.

1

No path to a transaction: no accounts, no pay buttons, no payment links.

2

Uncertain values are not read. Extract low or missing means silence.

3

Facts, not instructions. Not "you should pay", but "the letter says 73,000 won".

4

Never tells anyone to throw a document away.

5

Contacts and links extracted from the letter are never actionable. Calls go only to registry numbers.

Wording rule

No verified mismatch is the strongest thing we say. Never "genuine", "normal" or "safe". The screen shows what was checked, how many, and what was not.

Agent rules

Never types passwords or certificates · aborts if the amount differs · stops after 3 identical screens or 25 steps · done only after the pay click.

Why hand over

Authentication, passwords and consent are legal acts. The agent stops the moment it sees them and resumes only after the child presses [Continue]. Remote inputs pass through a queue, are never stored, and are cleared when the run ends.

Demo portal

The real Korean giro site requires a financial certificate even for guests, so lookups sit behind authentication. We run the same flow on a demo portal (always labelled "demo · no real payment") and show the real site up to its authentication wall. Connecting a real issuer means swapping the ledger for an API, not rewriting the agent.

DocDo9

Public sector · Gyeongbuk

Only one thing changes: who sits in the child's seat.

1 · Care workers' case management

A care worker photographs the mail on a visit; today's child screen becomes their case screen. Who got which bill, due when, handled or not, on record.

2 · Township offices and senior centers

Seniors without a phone use the same flow on a counter or senior-center tablet. The senior side has no account, so any device works.

3 · A Gyeongbuk issuer registry

Register official numbers and accounts for local tax and water bills across 23 cities and counties, and every public notice in Gyeongbuk becomes checkable. Data entry, not model work. Flagged patterns go back to local government and police.

4 · Public payment APIs

When Wetax or Giro open an API, we swap the ledger. The agent stays the same. A human still authenticates.

Helps the family when there is one. Lets the public sector take that seat when there isn't.

Limits · stated first

What these results do not say

Not detected

  • An impersonation letter that copies official contacts verbatim. Every value it carries is real, so a registry check passes it.
  • Sub-office names (e.g. "NPS Pohang Branch") cannot be told apart from fakes by structure alone. Both go to the child for review. We accept false positives to reduce misses.
  • We do not look up the real holder of a bank account. No authority. The screen says "not checked".

Next

  • Web push for the child: "a letter arrived", "your turn".
  • Registry growth from open government data, including local area-code ranges.
  • Real issuer APIs behind the same agent.
  • Show the child the original region of the photo using Extract coordinates, instead of reading the value.
